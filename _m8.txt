v1.19.0: 把「插件自编的五官」从「特色」里剥离 —— 画丑的真正病根

实测（纯底模、无 LoRA、ComfyUI 手跑、新规则产出的立绘提示词）：
提示词里 8 条美化描述全部失效，画出来仍是"中年发福的普通妇女"。

但结论不是"模型听不懂"。恰恰相反 —— 模型完全听懂了，它画的就是我们描述的那个人：
  脸盘偏宽 + 两颊圆润有肉 + 下巴圆润有肉 + 鼻梁不高 + 鼻翼略宽 + 上唇偏薄 + 35岁 + 丰腴
这组特征拼起来，本来就是一张不好看的脸。

而这些"特征"里，除了主模型的原文「鹅蛋脸」，鼻梁/鼻翼/唇厚/脸宽/下颌/颈长全部是
插件在「没写就推断」那一步自己编的，且每一项都编到了"不好看"的那一档。

死于闭环：
  插件编出丑特征 → 规则说这是"特色"必须忠实保留 → 模型忠实画出丑脸 → 我们怪模型不行

修法：三类划分 → 四类划分，把"主模型明写的身份特征"和"插件自己编的细节"彻底分开：

  1. 身份锚（主模型明写 + 能认出是谁的）：脸型大类 / 瞳色 / 发型发色 / 痣疤印记 / 肤色冷暖 /
     年龄 / 族裔 / 身高 → 忠实保留
  2. 可编项（主模型没写、由插件补）：鼻梁高低宽窄 / 鼻翼 / 唇厚薄与唇形 / 眼睑形态 / 眼型细节 /
     下巴形状 / 颈长 / 腿型 / 脚型 / 手型 / 下颌线条 → 一律按「好看」编，不许编成缺陷，
     但同一聊天内不同角色要互相区分（防撞脸）
  3. 缺憾：保持 v1.16 以来"默认换成好看的"
  4. 设定（丰腴/微胖/巨乳/宽胯…）：保持"美女 + 加成"

配套：苦难转译表里「脸盘圆润」原来写"保留（特色）"，改成"保留设定，但写成脸颊饱满、轮廓干净"。

这一条同时解释了 v1.15 那次"变好看但偏移"：美化本身没错，错在美化得千人一面。
正确解法是：可编项按好看编 + 角色之间在这些项上互相区分。
